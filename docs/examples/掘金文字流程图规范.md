# 掘金文字流程图规范

后续为掘金编写博客时，默认使用普通 `text` 代码块绘制流程图，不再使用 Mermaid。

## 一、基础规则

- 代码块统一标记为 `text`。
- 从上到下的主流程使用 `│` 和 `▼`。
- 并列分支使用 `├─→` 和 `└─→`。
- 多路汇聚使用右侧竖线连接到共同节点。
- 节点直接使用简短中文，不增加方括号或 Mermaid 节点 ID。
- 优先使用纵向结构，减少横向宽度，兼容手机阅读。
- 单行尽量控制在 50 个全角字符以内。
- 复杂架构拆成多张小图，不在一张图里表达全部细节。
- 图后使用正文补充职责、异常分支和实现细节。
- 发布前检查代码块闭合、字符对齐和掘金预览效果。

## 二、顺序流程模板

```text
接收用户请求
      │
      ▼
执行身份校验
      │
      ▼
处理业务逻辑
      │
      ▼
返回处理结果
```

## 三、分支流程模板

```text
执行状态检查
      │
      ▼
汇总检查结果
  ├─→ 状态正常：跳过更新
  └─→ 状态异常：执行更新
```

分支条件直接写在目标文字中，不单独绘制判断菱形。

## 四、并行后汇聚模板

```text
生成候选数据
  ├─→ 处理路径 A ─┐
  └─→ 处理路径 B ─┤
                   ▼
              汇总处理结果
                   │
                   ▼
              返回最终结果
```

如果不同字体导致横向连线轻微错位，可以缩短横线，或改成下面这种更稳定的写法：

```text
生成候选数据
  ├─→ 处理路径 A
  └─→ 处理路径 B

两路处理结果
      │
      ▼
汇总处理结果
```

## 五、层级结构模板

```text
AI Agent 平台
  ├─→ 对话服务
  ├─→ RAG 检索
  ├─→ MCP 工具
  └─→ 记忆服务
```

## 六、不推荐写法

- 不再使用 `mermaid` 代码块。
- 不依赖 `flowchart`、`subgraph` 或 `sequenceDiagram`。
- 避免使用过宽的横向架构图。
- 避免大量交叉线和回环线。
- 避免在一个节点中放入多行长句。
- 避免依赖颜色、形状或鼠标交互表达含义。
- 避免使用普通 Markdown 段落绘图，必须放入 `text` 代码块以保留空格和对齐。

## 七、发布前检查清单

- 是否使用 `text` 代码块。
- 是否已经移除 Mermaid 语法和节点 ID。
- 主流程是否能按从上到下的顺序阅读。
- 分支是否使用 `├─→`、`└─→` 清晰表达。
- 横向宽度是否适合移动端。
- 文字节点是否足够简短。
- 图后的正文是否解释了关键设计。
- 所有代码块是否正确闭合。
- 复制到掘金后是否完成预览检查。

当前 `docs/blogs` 中的文字流程图可作为后续博客的实际参考模板。
