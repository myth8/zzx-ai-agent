## 二、MySQL

### 连接信息

```
host      127.0.0.1
port      3306
user      root
password  underdog
database  zzx_agent_db
charset   utf8mb4
```

SQLAlchemy 连接串：

```
mysql+pymysql://root:underdog@127.0.0.1:3306/zzx_agent_db?charset=utf8mb4
```

命令行连接：

```bash
/opt/homebrew/opt/mysql@8.0/bin/mysql -u root -punderdog -h 127.0.0.1 --protocol=TCP
```

> `mysql@8.0` 是 keg-only 的，命令不在默认 PATH 里。若想直接用 `mysql`，执行：
> `echo 'export PATH="/opt/homebrew/opt/mysql@8.0/bin:$PATH"' >> ~/.zshrc`

### 路径

| 用途 | 路径 |
|---|---|
| 配置文件 | `/opt/homebrew/etc/my.cnf` |
| 数据目录 | `/opt/homebrew/var/mysql/` |
| socket | `/tmp/mysql.sock` |
| 错误日志 | `/opt/homebrew/var/mysql/error.log` |

`my.cnf` 内容（Homebrew 默认，仅限制本地访问）：

```ini
[mysqld]
bind-address = 127.0.0.1
mysqlx-bind-address = 127.0.0.1
```

### 关键参数

| 参数 | 值 |
|---|---|
| `character_set_server` | `utf8mb4` |
| `collation_server` | `utf8mb4_0900_ai_ci` |
| `max_connections` | 151 |
| `time_zone` | SYSTEM |
| root 认证插件 | `mysql_native_password` |

**认证插件特意设成了 `mysql_native_password`**，这样 PyMySQL 不依赖 `cryptography` 包就能连。MySQL 8.4 起该插件被移除，届时需要改回默认的 `caching_sha2_password` 并在 Python 环境里加装 `cryptography`。

### 库表

当前数据库 `zzx_agent_db`，迁移版本 **`20260918_0002`**（已执行到 stage1 数据完整性）：

| 表 | 用途 |
|---|---|
| `users` | 用户与角色 |
| `sessions` | 会话 |
| `chat_messages` | 消息 |
| `chat_summaries` | 对话摘要 |
| `chat_runs` | 对话执行记录 |
| `idempotency_records` | 幂等键 |
| `rag_documents` / `rag_document_chunks` | RAG 文档与切片台账 |
| `migration_orphan_records` | 迁移清理出的孤儿数据存档 |
| `alembic_version` | 迁移版本 |

### 常用命令

```bash
brew services start   mysql@8.0
brew services stop    mysql@8.0
brew services restart mysql@8.0
brew services list
```

数据库操作：

```bash
M="/opt/homebrew/opt/mysql@8.0/bin/mysql -u root -punderdog -h 127.0.0.1 --protocol=TCP"

$M -e "SHOW DATABASES;"
$M -e "USE zzx_agent_db; SHOW TABLES;"
$M -e "SELECT * FROM zzx_agent_db.alembic_version;"

# 备份（输出为纯 SQL，注意脚本里虽带 .gz 后缀但实际未压缩）
mysqldump -u root -punderdog -h 127.0.0.1 zzx_agent_db > backup.sql

# 恢复
$M zzx_agent_db < backup.sql
```

### 迁移

```bash
cd zzx-ai-agent-backend
conda activate zzx-ai-agent
alembic upgrade head
alembic current
alembic downgrade -1
```

`0001_legacy_baseline` 内部有「表不存在才建」的判断，所以对已有数据的库执行不会重复建表；`0002_stage1_data_integrity` 会补列、建索引、建 `chat_runs` 与 `idempotency_records`，并把孤儿数据移入 `migration_orphan_records` 后删除。

## 四、天气 MCP 服务（zzx_mcp_server）

后端的 `get_now_weather` 工具不是本地函数，而是通过 MCP 协议调用这个独立服务。**它不会自动启动**，忘了起会导致对话在调用天气工具时整轮失败。

### 连接信息

```
host      127.0.0.1
port      8000
path      /mcp
transport streamable-http
```

后端在 `app/llm/mcp_tools.py` 里硬编码了这个地址。

### 路径

| 用途 | 路径 |
|---|---|
| 服务目录 | `zzx_mcp_server/` |
| 配置 | `zzx_mcp_server/.env` |
| 启动入口 | `zzx_mcp_server/server.py` |

`.env` 需要 `SENIVERSE_API_KEY`（心知天气），缺失时 `validate_mcp_config()` 会直接抛错。

### 启动

```bash
cd zzx_mcp_server
conda activate zzx-ai-agent
python server.py
```

依赖 `fastmcp` 与 `httpx`，已包含在后端 `requirements.txt` 里，不用单独装。

验证：

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN      # 应看到 python 在监听
```

注意：用 `curl http://127.0.0.1:8000/mcp` 测试会返回 **406**，这是正常的——streamable HTTP 要求特定的 `Accept` 头，406 恰恰说明服务活着。真正的可用性验证走工具调用：

```bash
cd zzx-ai-agent-backend
python -c "from app.llm.mcp_tools import get_mcp_tools; print([t.name for t in get_mcp_tools()])"
```

期望输出 `['get_weather']`。

### 代理变量会拦截本机请求

如果启动后端的环境里存在 `HTTP_PROXY` / `HTTPS_PROXY`，httpx 会把发往 `127.0.0.1:8000` 的请求也交给代理，代理返回 **502**，表现为天气工具失败。

启动前加上排除规则：

```bash
export NO_PROXY="127.0.0.1,localhost"
export no_proxy="127.0.0.1,localhost"
```

## 五、与后端 `.env` 的对应关系

配置文件：`zzx-ai-agent-backend/.env`（已被 gitignore 保护，不会进仓库）

```ini
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=underdog
MYSQL_DB=zzx_agent_db

REDIS_URL=redis://127.0.0.1:6379/0
REDIS_AUTH_PREFIX=zzx:auth
RATELIMIT_KEY_PREFIX=zzx:ratelimit
```

改密码时**两边都要改**：MySQL 里执行 `ALTER USER`，同时更新 `.env` 的 `MYSQL_PASSWORD`，否则后端连不上。

## 六、启动与自检

```bash
# 0. 排除本机代理，避免 127.0.0.1 的请求被代理劫持
export NO_PROXY="127.0.0.1,localhost"
export no_proxy="127.0.0.1,localhost"

# 1. 起依赖服务
brew services start mysql@8.0
brew services start redis

# 2. 起天气 MCP 服务（独立终端，需保持前台运行）
cd zzx_mcp_server && conda activate zzx-ai-agent && python server.py

# 3. 自检
redis-cli ping                                                  # PONG
mysql -u root -punderdog -h 127.0.0.1 --protocol=TCP -e "SELECT 1;"

# 4. 起后端
cd zzx-ai-agent-backend && conda activate zzx-ai-agent && python run.py

# 5. 健康检查，期望 redis 为 ok、status 为 ok
curl -s http://127.0.0.1:8123/api/health
```

```json
{ "environment": "development", "mode": "ZZX-AI-AGENT", "redis": "ok", "status": "ok" }
```

## 七、常见问题

### 对话报「生成过程中出现异常」，日志有 `ExceptionGroup: unhandled errors in a TaskGroup`

天气 MCP 服务没起，或请求被代理拦了。`get_mcp_tools()` 内部 `asyncio.run(client.get_tools())` 连接失败时，anyio 的 TaskGroup 会抛 `ExceptionGroup`，堆栈里能看到：

```
httpx.HTTPStatusError: Server error '502 Bad Gateway' for url 'http://127.0.0.1:8000/mcp'
```

502 说明是代理转发的（服务根本没起时直连是连接被拒绝）。处理：

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN        # 空 → 起服务
cd zzx_mcp_server && python server.py

export NO_PROXY="127.0.0.1,localhost"   # 有代理变量时
```

### Redis 报 `MISCONF ... unable to persist to disk`

RDB 快照落盘失败，Redis 在 `stop-writes-on-bgsave-error=yes` 保护下拒绝所有写命令，接口会 500。

排查：

```bash
redis-cli INFO persistence | grep rdb_last_bgsave_status   # err 即落盘失败
ls -la /opt/homebrew/var/db/redis/                          # 出现大量 temp-*.rdb 说明卡在重命名
```

处理：

```bash
# 先看是否磁盘满
df -h /opt/homebrew

# 清理残留临时文件
rm -f /opt/homebrew/var/db/redis/temp-*.rdb

# 重启让持久化恢复正常
redis-cli shutdown nosave
brew services restart redis
redis-cli BGSAVE && sleep 2 && redis-cli INFO persistence | grep rdb_last_bgsave_status
```

**注意**：如果 Redis 是从受限的沙箱会话里启动的（例如被某个工具拉起），进程会继承文件操作限制，能创建 `temp-*.rdb` 但无法重命名为 `dump.rdb`，表现为持久化永久失败。这类情况必须**在正常终端里重启**，临时缓解可以 `redis-cli CONFIG SET save ""` 关掉快照（但重启后数据丢失）。

### 端口被占用

```bash
lsof -nP -iTCP:3306 -sTCP:LISTEN
lsof -nP -iTCP:6379 -sTCP:LISTEN
```

### 后端报 `Access denied for user 'root'@'localhost'`

`.env` 里的 `MYSQL_PASSWORD` 和数据库实际密码不一致。重置：

```bash
mysql -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'underdog';"
```

### 后端报 `RuntimeError: cryptography is required`

说明 root 被改成了 `caching_sha2_password`。要么改回 `mysql_native_password`（MySQL 8.0 可用），要么在 conda 环境里 `pip install cryptography`。

### 迁移报 `Table 'users' already exists`

说明库里已有表但 `alembic_version` 缺失。先标记基线再升级：

```bash
alembic stamp 20260918_0001
alembic upgrade head
```
